# Gizai v0.1: build notes

What was decided while building v0.1 (2026-10-06), what the final review found, and what is left for Jeffrey.
Plan: `docs/superpowers/plans/2026-10-06-gizai-v0-1.md`. Each line names what it costs if the call was wrong.

## Decisions for Jeffrey

1. **First real run.** Try one agent run with the real Claude Code on a small task (see README → Using it). Agents get the prompt on stdin; if a run fails, its error shows Claude Code's own message.
2. **Merge v0.1 into main** (local only, nothing is pushed), or keep working on the branch.
3. **Hold counters:** should clearing a hold reset a card's bounce and failed-run counts (a fresh 3 tries)? Now they are lifetime totals, so the next failure holds the card again.
4. **Budget warning:** the monthly agent budget now stops new runs at 100 %. Add a warning at 80 % and show the spend on agent cards?
5. **Second team:** a new team gets the six columns, but new projects still join the first team; moving projects between teams is not in v0.1.
6. **Doc autosave:** docs save on Ctrl+S, on leaving the editor and on leaving the page (every save is a version). Timed autosave?
7. **Agent command access:** the default allowed commands (npm, npx, composer, php, cargo, pytest, git commit, …) let an agent run any code in its worktree; there is no sandbox. Trim per agent on the Team page if wanted.

## Deferred (minor, from the final review)

- the run-limit check and insert are not atomic; one agent can get two runs via the Run button or racing dispatches; two starts can race inside worktree::ensure — reserve a slot under the live-map lock.
- Stop racing a natural finish marks a good run cancelled; the stopped set is never pruned.
- an invalid UTF-8 stdout line ends the reader (use read_until + from_utf8_lossy).
- post-exit group signal after reaping could in theory hit a reused pgid (check /proc first).
- turn counting may overcount parallel tool calls (count distinct message ids; check on the first real run).
- an explicitly chosen agent skips the hold check in the backend (the UI blocks it).
- run_events is sync and parses a whole log on the main thread (make async, last 500).
- qa_fail / no-result still raise counters on cards moved by hand to Done.
- cache tokens are summed into input tokens instead of cache_* columns; runs.exit_code never written.
- settings::set and touch_heartbeat skip the changes log; Writer::set_run unused.
- every description save logs the whole patch in changes (log a length/hash).
- detect_claude uses all of stdout, has no timeout, runs inside async start; it may resolve the mise shim; the desktop PATH may lack npm/cargo for agents.
- a worktree folder deleted by hand gives "already checked out at <same path>" (run git worktree prune first); a renamed task may cut a new branch (prefer tasks.branch).
- Tauri is imported outside api.ts in ProjectForm, FileDrop, MarkdownView (plan placed them there).
- incoming-* temp files after a failed copy and open/ copies are never cleaned up.
- no 80 % budget warning or spend shown on agent cards yet.
