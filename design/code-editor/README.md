# Code Editor D1: the Changes view, and colours for code and diffs (GA-104)

The design of GA-91's research §5.1 (the Changes view) and the values of §5.1 and §5.2's new tokens, for Jefsev's review.

- `changes.html` is the design. Open it from disk in a browser: it uses the app's own stylesheets in `src/styles/`, so it
  shows the app's components, type styles and tokens. Dark, Light or Both at the top; `t` switches, as in the app.
- `changes.css` is its stylesheet. The first part is the Changes view itself, all tokens (F1 builds it); the second part
  only lays out the page.
- `changes.js` makes the frames work: the carets, folds, Show buttons, file list, filter and keys, as F1 should.
- `new-tokens.json` holds the 21 new tokens in `design/tokens.json`'s format, for F0.
- `gen-changes.mjs` builds `changes.html` from `changes.template.html`, writes `new-tokens.json` and the tables below. It
  parses the code with Lezer's own grammars and checks the colours against the card's rules (4.5:1 on `bg` and
  `raised`, no teal or magenta) before it writes anything. Run it with `node design/code-editor/gen-changes.mjs`; until F0
  adds `@codemirror/lang-php` and `lang-rust`, its first lines say how to give it the PHP and Rust grammars.

Nothing in the app changes in this card: F0 puts the tokens and these rules into the app, F1 builds the view.

## Rules for design/README.md

F0 adds this section under Visual foundations, after "Colour carries meaning, never decoration".

> **Code and diffs.** Code (the Changes view, the Editor, code in Markdown) has colours of its own: `syn-*` for syntax and
> `diff-*` for changes. They appear only inside code: never on buttons, badges, status, labels or charts.
>
> - **Changes are green and red of their own.** An added line has `diff-add-soft` behind it and a removed line
>   `diff-del-soft`; the characters that changed get `diff-add-strong` or `diff-del-strong` on top. The + and − marks, a
>   changed line's number, the A and D letters and the counts (`+964 −112`, in mono) are `diff-add` and `diff-del`. A fold
>   bar is `diff-fold` with `text-2`. They're near `success` and `danger` but separate: those mean run and form outcomes,
>   so neither stands in for the other.
> - **Syntax uses four hues and the greys.** Violet `syn-keyword` (and `syn-meta`), blue `syn-function` (and `syn-tag`),
>   gold `syn-type` (and `syn-attribute`), orange `syn-string` (and `syn-number`). Names stay `text`, operators and
>   punctuation `text-2`, comments `syn-comment`. `syn-invalid` is `danger` with a wavy underline.
> - **No teal or magenta in code**: they mean an agent at work and "needs you". **No green or red in syntax**: they mean
>   added and removed.
> - **Contrast:** every syntax and diff text colour is at least 4.5:1 on `bg` and `raised` in both themes, and on changed
>   lines; on a changed word every one but comments (3.4:1 in dark) and `syn-invalid`. Check a new value against all four
>   before it goes in.
> - **Never colour alone:** changed lines keep their + or −, removed lines their old number, status letters their word
>   (tooltip and screen readers), and "Not committed" is written in the file's header.
> - **Type:** code is `t-code` in `--font-mono`, which Settings → Appearance changes as everywhere. No italic or bold for
>   syntax: the bundled fonts have no italic, and colour already does the work. In text, write arrows with Lucide's
>   `arrow-right`: → isn't in Atkinson Hyperlegible's files (↑ and ↓ are).

themes.

## Which Lezer tags get which token (F0, `src/lib/codeTheme.ts`)

| Token | Lezer tags |
|---|---|
| `syn-keyword` | keyword (and controlKeyword, definitionKeyword, moduleKeyword, operatorKeyword), self, atom, modifier |
| `syn-meta` | meta (and processingInstruction, documentMeta, annotation), escape, special(brace) |
| `syn-function` | function(variableName), function(propertyName), macroName |
| `syn-tag` | tagName, standard(tagName) |
| `syn-type` | typeName, className, namespace, special(variableName) (Rust's lifetimes) |
| `syn-string` | string (and character, attributeValue, docString), special(string), regexp, url |
| `syn-number` | number (integer, float), bool, null |
| `syn-comment` | comment (lineComment, blockComment, docComment) |
| `syn-attribute` | attributeName |
| `syn-property` | propertyName, special(propertyName), definition(propertyName) |
| `syn-variable` | variableName, definition(variableName), name, labelName, content |
| `syn-operator` | operator (and all its kinds), function(punctuation) (`=>`) |
| `syn-punctuation` | punctuation (separator, paren, brace, squareBracket, angleBracket) |
| `syn-invalid` | invalid |

Blade (F0's own language, on the model of lang-liquid): HTML around; PHP inside `{{ }}`, `{!! !!}`, a directive's brackets
and `@php … @endphp`; directives (`@if`, `@foreach`, `@can`) as keywords; the delimiters as meta; `{{-- --}}` as a comment.
